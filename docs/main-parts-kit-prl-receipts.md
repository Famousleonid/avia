# Main Parts: общий источник KIT/PRL и получение

Изменение выполнено локально 23/Sep/2026. Продакшин не изменялся.

## Что изменилось

- Main использует `TdrPrintFormController::kitRows()` и `prlRows()` — те же построители, что печатные KIT и PRL. Сначала идут KIT, затем PRL. Сохраняются варианты P/N, количества, покрытие KIT, исключение дублей и зачёркнутые позиции.
- Зачёркнутые позиции видны как в форме, но не имеют редактирования PO/Received и не считаются зелёными. Rows включает все показанные строки, включая зачёркнутые. Числа на иконках могут иметь другую единицу подсчёта: например PRL считает количество деталей, окно — строки.
- Для обычных TDR сохраняются прежние поля `po_num` и `received`. Для генерируемых строк добавлена таблица `workorder_part_receipts`: WO + идентификатор строки, PO, дата получения. Искусственные TDR при вводе не создаются.
- Идентификатор не зависит от места в списке. Для генерируемых строк он учитывает количество и активные варианты: старое получение не переносится на изменённую позицию. Старые записи остаются в БД.
- Исторический TDR, исключённый из PRL из-за покрытия KIT, используется в KIT только при однозначном совпадении компонента и количества. Неоднозначные исторические связи автоматически не угадываются; исходные TDR не удаляются.
- Сохранённый PO отображается и в соответствующей печатной форме. Получение остаётся в Main, где предусмотрено это поле.
- Зелёные только три правых поля после заполнения PO и даты. PO по умолчанию открыт для номера. Ввод PO сам по себе больше не записывает сегодняшнюю дату получения.
- Сохранение использует штатный `window.confirmDialog`; отмена восстанавливает сохранённое значение. При недоступном подтверждении запись запрещена.
- `Transfer from WO` теперь доступен также для генерируемых строк без TDR. Источник — сохранённая Log Card другого WO того же мануала, с подходящим P/N. Обе Log Card остаются неизменными. Дополнительные файлы и миграция: [Переводы из Log Card](main-log-card-transfers.md).
