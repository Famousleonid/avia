## Что делает форма

- Иконка **In-Process Check Sheet** перед **TDR Form** открывает отдельную печатную страницу.
- Задания, номера этапов, references, подписи полей и пустые строки берутся из XLS конкретного основного мануала WO. Другой мануал не используется как запасной шаблон.
- WO и Master P/N берутся из текущего заказа; описание, производитель, точный номер и library — из данных AVIA. Значения образца WO/P/N и подписи из Excel не импортируются.
- Штампы остаются пустыми. Электронное выполнение/подписание не входит в эту версию.
- Это полный лист мануала, а не автоматический вывод о применимости каждого задания к ремонтируемому узлу. Условные инструкции (например, JAZZ-only) сохранены дословно; выполнение не отмечается автоматически.
- Без импортированного шаблона показывается понятное сообщение, а не общий список. Старые Parts/ASSY/STD/TDR/Log Card и история WO не изменяются.
- При повторном открытии используется текущая версия шаблона мануала; это не архив ранее подписанного листа.

## Что перенести

Архив `output/in-process-check-sheet-20260917.zip` содержит новые файлы с путями относительно корня Laravel, точечный patch трёх существующих файлов и SQL. В patch **не включены** остальные незавершённые изменения рабочей копии.

1. Скопировать файлы из `new-files/` в корень Laravel с сохранением путей:
   - `app/Http/Controllers/Admin/InProcessCheckSheetController.php`
   - `app/Models/ManualInProcessCheckSheet.php`
   - `resources/views/admin/tdrs/in-process-check-sheet.blade.php`
   - `database/migrations/2026_09_17_140000_create_manual_in_process_check_sheets_table.php`
   - два сервиса `app/Services/InProcessCheckSheetImporter.php`, `app/Services/InProcessCheckSheetSql.php` (нужны для инструментов импорта; страница сама XLS не читает).
2. Внести **только** изменения из `existing-files.patch`:
   - `routes/web.php`: маршрут `tdrs.inProcessCheckSheet` рядом с `tdrs.woProcessForm`, внутри существующей auth/verified/desktop группы;
   - `resources/views/admin/tdrs/show.blade.php`: новый paper-button непосредственно перед TDR Form;
   - `app/Providers/AppServiceProvider.php`: добавить `admin.tdrs.in-process-check-sheet` в список printFormViews, чтобы Debugbar не попадал в печать.
   Не заменять эти три файла целиком копиями из рабочего дерева: в них есть другие изменения. Patch можно применить к локальной копии актуальных production-файлов и загрузить результат обычным способом.
3. Один раз выполнить `in_process_check_sheet_20260917_v01_schema.sql` в production базе через phpMyAdmin. Он создаёт **только одну новую постоянную таблицу**; временных таблиц и удаления данных нет. Альтернатива — выполнить только новую Laravel migration (не обе операции).
4. Выполнить нужные `*_20260917_v02_check_sheet_import.sql` из папок мануалов или `sql/` архива. Ожидаемые результаты: `READY`, затем `SUCCESS`. При `BLOCKED` не пытаться принудительно обходить проверку — сравнить текущий шаблон.
5. Файлы `*_verify.sql` содержат только SELECT. Их можно запустить самостоятельно, но достаточно сообщить «залил» — агент проверит production в режиме read-only.

Если в deployment используются кэшированные маршруты/шаблоны, обновить их вашим обычным способом после загрузки файлов. Агент не выполняет production deployment/cache-команды.
