Точки и правила CMM

Как завести точку измерения на фигуре, добавить к ней параметр (замер или инспекцию) и настроить правила ремонта — с порогами по превышению и условными процессами. Все экраны сняты на реальном мануале 32-31-02 (Rod, Retraction Actuator MLG).

1

Добавить точку на фигуру

Manuals → 32-31-02 → вкладка Dimensions → фигура в списке Figures

  • Add Point — обычная точка замера: клик по кнопке, затем по месту на фигуре. Код точки присваивается следующим по порядку.
  • Add Callout — точка с выноской: маркер-точка на детали + рамка с номером в стороне. Удобно для мелких мест — именно так поставлена точка 7 (Anti-rotation Key).
  • Add Area / Add Circle / Add Line / Add Label — зоны и пометки без замера; View — стрелка «вид».
  • Точку можно перетаскивать мышью; Find point… находит точку по коду; Edit Point в панели справа — код, описание, галочка F&C.
F&C. Галочка «Fits & Clearances» на точке нужна только посадочным парам (точки 5 и 6) — они попадают в F&C-поток и документ. Инспекционным точкам вроде keys она не нужна.
2

Панель точки

клик по точке на фигуре → панель справа

В панели видно всё, что привязано к точке: деталь (ROD), параметры с кодами дефектов и их правила. Отсюда же всё и заводится:

  • + Add Parameter (внизу) или + Param у детали — добавить параметр к точке;
  • + Add rule под параметром — добавить правило ремонта;
  • карандаш у параметра / правила — редактирование;
  • Copy setup from point… — скопировать полную настройку с другой точки (параметры, коды, правила) — для одинаковых мест.
3

Параметр: замер или инспекция

панель точки → + Add Parameter

  • Part — деталь, к которой относится замер (по ней собирается план ремонта и TDR).
  • Description — что меряем: OD, ID, состояние поверхности.
  • Required — точка обязательна: без initial-записи по всем обязательным параметрам кнопка Update в WO не активируется. Record actual value — требовать числовое значение.
  • Defect Codes — какие дефекты здесь можно найти, с контекстом: Inspection — дефект видят при осмотре (Damage, Corroded); Measurement — дефект следует из замера (Worn).
  • Dimensional limits — Orig Min/Max из мануала. Wear — если пусто, используются оригинальные (так и работает: wear-лимиты есть не у всех). Repair limits / Repair Steps — размер после ремонта и ступени oversize.
  • Для чисто инспекционной точки (keys) лимиты оставляют пустыми — точка принимает только finding или «чисто».
  • In-process check — точка меряется по ходу маршрута (например, база после снятия хрома), а не на входной инспекции: не блокирует кнопку Update и живёт отдельной секцией в панели (см. шаг 9).
4

Правило: маршрут ремонта и пороги

панель точки → + Add rule (или карандаш у правила)

Правило = один маршрут ремонта этого места: когда он включается (Triggers) и что делается (Processes, по порядку технологии).

Action

  • Repair — маршрут попадает в план ремонта; Order new — деталь заказывается; EC — концессия.

Triggers — когда правило срабатывает

  • Размерные: Above / Below orig (или wear) — замер вне лимита. У размерного триггера есть порог превышения Δ: поле over > Δ и up to ≤ Δ. Так разводятся маршруты одного места: Silver restoration — Δ ≤ 0.010 (в толщину слоя серебра), Machining + chrome — Δ > 0.010. Ровно на пороге выбирается нижняя полоса (Silver).
  • Finding — Inspection / Measurement / NDT с кодом дефекта: техник выбрал дефект при замере → правило включилось. NDT-контекст — для вердиктов после контроля (шаг 8).
  • Final out of limits — FAIL финального замера (после ремонта не попали ни в repair-лимиты, ни в oversize-ступень). Обычно на EC-правиле (шаг 10).
Как выбирается маршрут в WO: ввели только цифру — по размеру и полосе Δ; выбрали дефект — по finding-триггеру. Если точке подходит несколько правил сразу — превью Update покажет выбор (радио).

Processes — что делается

  • Порядок строк = порядок технологии; перетаскивание за ⠿.
  • Чип point / part — охват процесса: строка на каждое место или одна на деталь (part-строки с одинаковой операцией сливаются между маршрутами: один NDT, одна ванна). Клик по чипу переключает.
  • Поле notes — заметка в план и печать (например «fig. 6039»); ⚓ — якорь EC-гейта.
5

Условия на процессе — кнопка «if»

модалка правила → кнопка if на строке процесса

Строка маршрута может включаться в план по условию — в зависимости от того, что ещё есть в собранном плане детали. Клик по кнопке циклом:

  • if — всегда (по умолчанию);
  • if+ — только если в плане есть выбранный процесс;
  • if− — только если выбранного процесса в плане нет.

Рядом появляется выбор процесса-условия. Пример использования: NDT-4 в silver-маршруте до серебра, когда хром не перекладывается (if− Chrome plating), и общий NDT-4 после серебра, когда хром-маршрут в плане (if+ Chrome plating).

Роду условия не понадобились: нужный порядок (NDT-4 после хрома, до серебра) получился из последовательностей самих маршрутов. Условия — инструмент на случаи, когда порядок должен меняться от состава плана.
6

Проверка в Workorder

WO → TDR → Inspect на строке детали → замеры → Update Processes

  • Внесите initial по всем обязательным точкам детали (инспекционные — finding или «чисто»).
  • Update Processes открывает превью: таблица будущего плана по порядку, с операциями и статусами (new / started / = / removed) и выбором маршрута, если подходят несколько правил. Apply changes — применить.
  • План собирается сам: механика (Machining) — первой (in-house, деталь уезжает к вендору один раз), part-строки с одинаковой операцией сливаются, идущие подряд NDT объединяются в одну строку.

Текущий план wo107903 после Apply (замеры: ID Worn 2.3760 → Silver, остальное чисто):

2Silver platingAMS-2410, 0.003–0.005 in, bake 8h @ 190°C

7

Заказ деталей из маршрута

модалка правила → блок Order parts

Маршрут может требовать заказ деталей: у рода оба маршрута замены bearing декларируют «BEARING, SPHERICAL ×1». При применении маршрута превью Update предложит заказ, Apply поднимет связанный Order New TDR (виден в Ordered Parts и PRL, код/condition — от ремонтного TDR).

  • Дедуп по позиции IPL: варианты одной позиции (1-380 / 1-380A) — один заказ; тот же P/N на другой позиции (1-400 у цилиндра) — отдельный.
  • Вариант позиции выбирается по assy-группировке Parts: какой род — такой bearing (заполните assy у вариантов).
  • Уже заказанное (вручную или авто) показывается жёлтой строкой «Already ordered» — дубль не создаётся.
  • Заказ, который плану больше не нужен, предлагается к отмене галкой; PO-номер или приёмка блокируют отмену.
8

NDT-вердикт и scrap

Inspect → точка → Add NDT / in-process finding → Update

Вердикт по ходу ремонта (NDT после стрипа/расточки, инспекция отверстия после снятия bearing) вводится красной кнопкой на точке: без значения, только код дефекта (контекст NDT — например Crack). Маршрут места определяет последний вердикт: NDT-crack, введённый после размерного FAIL, заместит прежний маршрут — превью покажет смену. Ошиблись — удалите запись крестиком, Update вернёт прежний план.

  • Правило с триггером «Finding — NDT» и действием Repair — ремонтный маршрут (weld …), процессы вольются в план.
  • Действие Order new = scrap: деталь-носитель списывается. Превью предложит заказ сборки (Rod Assy — по assy-привязке рода) с кодом Failed NDT, а связанные заказы (bearing) — к отмене: он входит в заказываемую сборку.
  • Work completed through — до какого процесса работа физически дошла (по умолчанию — первая NDT-строка, а если списание идёт после отказа EC — строка EC, см. шаг 10): строки до точки остаются записью выполненного для сопроводиловки, хвост удаляется. Строки с датами не удаляются никогда.
  • При подтверждении списания в notes воркордера дописывается запись «Scrap — Rod P/N … S/N … — Failed NDT» — что списали и почему; несколько деталей — по строке на каждую. Отменили списание (удалили вердикт, Apply вернул план) — строка этой детали удаляется сама.
9

In-process контроль (база после strip)

параметр с галкой In-process check

Контроль, который выполняется посреди маршрута — например замер базового металла после снятия хрома (минимум = максимально допустимая толщина будущего хрома). Такая точка:

  • не требуется для активации Update на входной инспекции и не влияет на индикатор готовности детали;
  • в панели Inspect живёт секцией «In-process checks (mid-route)»;
  • правила на ней обычные: «ниже минимума» → scrap (заказ сборки, шаг 8) или EC/ремонт — как в CMM.

У рода заведён параметр «Base metal dia (after strip)» на точке 5 — лимиты-заглушки, уточните по CMM.

10

EC-концессия: подача, отказ, продолжение

правило с действием EC → вердикт → Update → оранжевый блок EC — submit for concession

EC возникает в двух случаях: damage / corrosion на поверхности, где в CMM нет ремонта (референс-кейс рода: после chrome strip нашли damage базового металла), и после ремонта вышли из мин/макс размеров (финальный замер не попал ни в repair-лимиты, ни в oversize-ступень). Дефект уходит в OEM на концессию, работа встаёт до ответа.

Настройка (один раз, в мануале)

Быстрый способ — кнопка Std рядом с «+ Add rule» у параметра: готовые пакеты «NDT failed — scrap (Crack)», «EC package (Damage → EC, EC denied → scrap)» и «Final out of tolerance — EC». Один клик создаёт код на параметре + правило со стандартными именами; повторный клик ничего не дублирует. Дальше правило можно открыть и подправить (код, триггеры).
  • Нет ремонта в CMM: правило «Base damage — EC (concession)» на параметре поверхности: действие EC, триггер Finding — NDT · Damage (или Corroded).
  • Не попали в размер после ремонта: правило «Repair out of tolerance — EC (concession)»: действие EC, триггер Final out of limits (группа «Final (after repair)») — срабатывает на FAIL финального замера. Финал, принятый oversize-ступенью или repair-лимитами, триггер не включает. У рода заведено на OD (т. 5) и ID (т. 6).
  • Код «EC denied» (контекст NDT) на точках 5 / 6 / базы + правила «EC denied — scrap» (действие Order new, триггер Finding — NDT · EC denied) — для ввода отказа OEM.

Подача концессии

  • Техник вводит вердикт Damage по точке базы (красная кнопка «Add NDT / in-process finding») — или просто сохраняет финальный замер, вышедший из лимитов (триггер Final сработает сам).
  • Update Processes → оранжевый блок «EC — submit for concession: Concession: {точка} {описание} — {код}», галка включена по умолчанию. Пока галка включена, таблица показывает план «как будет»: выполненные строки на месте, строка EC на своей позиции, хвост помечен held; снимите галку — увидите обычный дифф пересборки.
  • Apply: план не пересобирается — выполненные строки остаются записью работы. В план перед NDT (гейт-якорем) вставляется строка EC с причиной, а незапущенный хвост после якоря удаляется — работа держится до ответа OEM. Юнит появляется на странице /ec.
#Process
1Chrome strippingвыполнено — остаётся записью
2ECConcession: 5 Base metal dia (after strip) — Damage
3NDT-1ждёт ответа OEM

Повторный Update дубль не создаёт — блок покажет «EC already on the plan».

Ответ OEM

  • Отказ — вердикт с кодом EC denied по той же точке → Update → scrap-флоу шага 8 (Rod Assy · Failed NDT · отмена bearing). «Work completed through» по умолчанию встаёт на строку EC — NDT после неё не выполнялся и уходит в dropped, а запись об EC остаётся в истории. В notes воркордера — строка «Scrap — … — Failed NDT (EC denied)».
  • Согласие — отдельного кода нет: техник продолжает маршрут (закрывает/удаляет EC-строку, Update возвращает удержанный хвост).
  • Ошиблись — удалите вердикт крестиком: Update переармируется и вернёт прежний план; notes-запись о списании снимется автоматически.
