# Общие правила AVIA

R&M editor (26/Oct/2026): левая таблица заполняется видимыми TDR (use_tdr) с Necessary=Repair, в порядке TDR; ключ строки tdr:<id>. Выбранные справа шаблоны добавляются с ключом record:<id>. Индивидуальные тип Repair/Modification/SB, описание, маркировка и номер сохраняются в workorders.rm_report.editor_rows, отдельно от общих шаблонов. Удаление ремонтной строки хранит deleted для этого WO, не удаляет TDR; снятие шаблона не удаляет шаблон мануала. Печать использует тот же WorkorderRepairRows. Сервер проверяет принадлежность ключей WO/выбранным шаблонам; конверсия ASSY остаётся привязана к выбранной справа SB-записи, а не к текстовому выбору SB в строке.

Язык ответов: всегда отвечай пользователю на русском языке, если он явно не попросил другой язык.

Права доступа: новые и изменяемые персональные права размещать в System > Access, где назначается кто что может. Не добавлять такие checkbox в Users Create/Edit. Перенос управления правами не должен сбрасывать существующие назначения; сохранять единый источник данных и серверные проверки полномочий.

Log Card order (23/Oct/2026): общий порядок хранится в manuals.log_card_order отдельно для каждого Manual и применяется к активным WO; QA-заблокированные карты и завершённые WO сохраняют записанный порядок. Изменение доступно isSystemAdmin или назначенным через System > Access > Manuals > Manage Log Card order (manuals.log_card_order), без автоматического доступа Manager. Проверять право и на кнопке, и на index/preview/update. Изменения логировать в manual_log_card_order: автор, Manual, порядок до/после и сведения IPL/P/N.

Не менять Qty на 1 ради обхода. Проверены один/несколько доступных родителей, сохранение, повторное открытие, очистка первого экземпляра, печатные P/N и S/N обеих строк; production при разработке не изменялся.

Для UI/CSS задач работай медленнее и проверяй не только целевой div, но всю цепочку layout сверху вниз:
container -> page wrapper -> card -> card-body -> form -> row/grid -> column -> inner scroll area.

Перед тем как сказать, что fixed:
1. проверь родительские ограничения по width/height/min-height/overflow/display/flex/grid;
2. ищи причину на уровень выше, а не только в проблемном блоке;
3. если задача про scroll, обязательно проверь, откуда берётся ограниченная высота;
4. если задача про width/columns, обязательно проверь, что проценты считаются от нужного родителя;
5. не останавливайся на первом правдоподобном патче — доводи до реальной причины;
6. в ответе коротко указывай root cause, а не только что поменял;
7. для простых CSS/UI багов сначала делай диагностику структуры, потом patch.

При спорных визуальных багах предпочитай более глубокую проверку, даже если это медленнее.

Общее правило диагностики для этого проекта:
- Нельзя закрывать задачу на уровне "теория не сработала", "не угадал" или первого правдоподобного патча.
