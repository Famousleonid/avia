# Общая база правил и навыков AVIA

Единый источник для всех рабочих мест — этот Git-репозиторий. Каталог составлен 17/Oct/2026. Здесь перечислены все найденные проектные правила и оба специализированных навыка AVIA; общие плагины перечислены отдельно как зависимости, а не как собственные навыки проекта.

## Правила

Полный обязательный текст: [rules/project.md](rules/project.md). Корневой [AGENTS.md](../AGENTS.md) направляет каждого агента к нему.

| Название | Краткие правила |
| --- | --- |
| Язык общения | Русский, если пользователь не запросил другой язык. |
| Персональные права | Управлять через System > Access; сохранять назначения и серверные проверки; не добавлять права в Users Create/Edit. |
| Диагностика UI/CSS | Проверять всю цепочку родителей, размеры, overflow, flex/grid; установить источник ограниченной высоты и базу процентов ширины; сначала диагностика, затем исправление. |
| Уведомления и подтверждения | Только showNotification и confirmDialog; без alert/confirm/prompt и системного beforeunload; при отсутствии внутреннего подтверждения останавливать действие. |
| Laravel-тесты | Запускать последовательно: общая testing-БД не допускает параллельных artisan test. |
| Диагностика данных и логики | Пройти route → controller/service → query/model → реальные данные → ответ/рендер; проверить исходный сценарий после исправления; сообщить установленную причину. |
| UI-состояние | Хранить per-user в user_ui_settings через UserUiSettings/UserScopedStorage/UserScopedSessionStorage; без browser storage. |
| Даты | Отображать dd/Mmm/yyyy; format_project_date / @projectDate; ввод через parse_project_date; ISO оставлять для технических контрактов. |
| База Quantum | Сначала читать quantum/; подтверждённые факты обновлять в первоисточнике, гипотезы — в open-questions.md; выгрузки — в quantum/log/. |
| Локальный вход для QA | Использовать ignored browser-admin-login.json; не публиковать пароль. |
| Импорт мануалов | Проверять manual/ID, каждую FIG, Parts, группы, процессы и SB; KIT только по явному CODE=KIT; quantities сохранять, буквенные/пустые нормализовать в 1. |
| Учёт импорта | Обновлять processed-manuals.md после каждого этапа; complete только при полной доказанной сверке; production-статистику отделять от локального журнала. |
| Production | Только чтение на актуальном SSH-сервере, проверка pinned host key; без изменений БД/файлов, деплоя, jobs и cache clear; SQL выполняет пользователь. |
| Архивный мост | По умолчанию только диагностика: SSH → log → task → process → API → конкретный файл → acknowledgement; ручной sync и изменения требуют явного разрешения. |
| Секреты | Ключи, пароли, bearer tokens, .env и сессии не выводить и не коммитить; доступы настраиваются отдельно на каждом рабочем месте. |

## Проектные навыки

### avia-import-manual-package — сканы мануала в базу

[Инструкция](skills/avia-import-manual-package/SKILL.md)

- Принимает каталог с FIG/IPL PDF, процессным XLS/XLSX и номер мануала.
- Рендерит сканы, проверяет OCR по изображениям, извлекает IPL/P/N, названия и количества.
- Строит и сверяет Part Groups, ASSY, альтернативы, Original/Oversize и KIT.
- Сопоставляет LLP/Log Card, NDT, CAD, Paint, PRL/KIT, Service Bulletins и In-Process Check Sheet; сохраняет исходный порядок Log Card.
- Выполняет dry audit по реальным данным, выявляет конфликты, сохраняет существующие ID и несвязанные данные.
- Применяет проверенный импорт локально; готовит версионные production SQL и SELECT-only проверку; сверяет результат после импорта пользователем.
- Ведёт [журнал мануалов](skills/avia-import-manual-package/references/processed-manuals.md) по FIG и этапам.

### avia-traveler-workbook — Excel в шаблоны Traveler

[Инструкция](skills/avia-traveler-workbook/SKILL.md)

- Инвентаризирует XLS/XLSX, включая скрытые листы, формулы, объединения, зачёркивания и цвета вкладок.
- Отбирает только подходящие зелёные вкладки с точным P/N, manual и подтверждённым Traveler layout.
- Сохраняет шаги, технические требования, единицы, условия и повторяющиеся операции.
- Разделяет Specification и дополнительные Description; исключает примерные WO/SN/RO, подписи и результаты.
- Сверяет процессы, группы и Parts, готовит dry-run и идемпотентный локальный импорт.
- Готовит отдельные production SQL и SELECT-only проверку; не применяет шаблоны к существующим WO.
- Ведёт источник/hash и раздельные статусы подготовки, локального импорта и production-проверки.

## Вспомогательные навыки среды

Эти навыки предоставляются Codex/плагинами, а не AVIA. Их доступность на другом рабочем месте нужно проверить; копировать весь локальный plugin cache в репозиторий не следует.

| Навык | Умение |
| --- | --- |
| pdf:pdf | Чтение, рендер, извлечение и визуальная проверка PDF. |
| spreadsheets:Spreadsheets | Чтение и изменение XLS/XLSX/CSV, формулы, форматирование и проверка. |
| build-web-apps:frontend-testing-debugging | Проверка страниц, поведения, адаптивности и ошибок браузера. |
| computer-use:computer-use | Работа с доступным браузером/интерфейсом для визуальной QA. |
| skill-creator | Создание и обновление переносимых SKILL.md, references и scripts. |
| openai-docs | Проверка актуальной документации Codex и подключения навыков. |

Остальные установленные навыки общего назначения (презентации, изображения, Pages, Sites и т. п.) не являются правилами AVIA и не подтверждают их использование в проекте.

## Подключение другого рабочего места

1. Получить актуальную версию этого репозитория через Git. Перед обновлением сохранить собственные незакоммиченные изменения; не применять reset/clean для синхронизации.
2. Открыть корень проекта в Codex. Прочитать AGENTS.md и rules/project.md, затем нужный SKILL.md из этого checkout.
3. Проектные навыки лежат в стандартной `.agents/skills/`. Если список навыков не обновился, открыть новую сессию; инструкции можно явно указать по пути.
4. Не использовать устаревшую личную копию avia-traveler-workbook или avia-import-manual-package вместо репозиторной. Личная копия на исходном компьютере автоматически не удаляется.
5. Установить зависимости проекта и необходимые инструменты: PHP/Composer/PhpSpreadsheet, Python и библиотеки, указанные используемым скриптом; PDF renderer для сканов. Проверить доступность до запуска.
6. Пути C:\Airplane и C:\template traveler — принятые исходные каталоги. На другом компьютере уточнить фактический путь; не заменять проверку источников догадкой. Ключи, логины, БД, исходники и run artifacts через эту папку не распространяются.

Документация: [Skills](https://learn.chatgpt.com/docs/build-skills), [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

## Как пополнять

- Общее требование AVIA: изменить rules/project.md; алгоритм конкретной работы: соответствующий SKILL.md/reference/script; Quantum-факт: quantum/; результат конкретного мануала: журнал и run artifacts.
- Вносить подтверждённое правило в первоисточник, исправляя устаревшую запись. Не превращать частное решение одного мануала в универсальное правило. Не заявлять непроверенное как факт.
- Новый навык создавать в skills/<name>/SKILL.md с YAML name и description, описанием входов, процесса, ограничений и проверки; добавить строку/раздел в этот каталог.
- Проверять ссылки и переносимость путей; для изменённых скриптов запускать подходящие проверки, для нового навыка — quick_validate.py из skill-creator, когда доступен.
- Перед публикацией проверить diff: только относящиеся к задаче файлы, без секретов, дампов, исходных PDF/XLS и чужих незавершённых изменений.
- Обмен изменениями — обычный Git commit/push и review/PR по принятому в команде порядку. Другие рабочие места получают обновления после Git pull; автоматической синхронизации личной памяти или плагинов нет.
- При конфликте журнала объединять доказанные результаты по manual/FIG, сохраняя расхождения явно; не выбирать целиком одну сторону и не терять чужую работу.
